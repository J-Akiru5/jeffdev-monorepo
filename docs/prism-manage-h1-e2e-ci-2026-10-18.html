Summary

prism-manage now has a real end-to-end test suite: 21 Playwright tests across 9 spec files, running against the actual app with a real Supabase account — and it is wired into CI as a gated job that runs on every prism-manage change. The suite passed 21/21 in 2.2 minutes, zero flakes. More importantly, building it immediately paid for itself: the first runs exposed seven real defects — including a critical RLS bug that silently emptied every user's workspace list, a production-runtime server action error, and two UI components that real users could not click. All are fixed, verified by the suite, and covered by regression tests.

Defects Found & Fixed

CriticalRLS infinite recursion on workspace_members — every user saw zero workspaces
The "Founders can manage workspace members" policy (FOR ALL) contained a subquery on the same table. Any query reading another member's row — including the layout's workspaces!inner embed — threw infinite recursion detected in policy for relation "workspace_members". Result: the app shell rendered but every authenticated user's workspace list was empty ("No Workspace Found" on the dashboard, no switcher).
Fix: new migration 20261018000006 — founder/member checks moved into SECURITY DEFINER helper functions (is_workspace_founder, workspace_has_members), policies recreated on top. Applied to the live DB via direct pooler connection (the CLI's login-role endpoint 403s — see Notes). Verified as the E2E user: memberships + workspaces!inner join now resolve.
High"use server" file exported objects — module crash at runtime
app/actions/pages.ts exported three zod schemas as export const from a "use server" file. Turbopack builds it, but the production runtime throws A "use server" file can only export async functions, found object when the actions chunk is evaluated — breaking every route that imports it.
Fix: schemas are now internal constants (nothing imported them externally).
HighDashboard crashed when rendering EmptyState from a server component
The dashboard (server component) passed icon={Building2} — a component function — across the RSC boundary into the client-only EmptyState. React refuses functions server→client: the "No Workspace Found" branch crashed instead of rendering.
Fix: EmptyState (@syntaxure/ui) now accepts a component or a pre-rendered element (isValidElement discriminator); dashboard passes icon={<Building2 />}. Additive — all existing call sites unchanged.
HighNotification panel's close button was unclickable (broken containing block)
The panel (fixed … h-full) rendered inside the navbar, where an ancestor establishes a containing block — so "full height" resolved against the ~56px bar and the footer landed on top of the header, intercepting clicks on the ✕. Playwright refused to click it for 60s; a real user couldn't either.
Fix: panel now renders via createPortal to document.body; close button got an aria-label.
HighTask row action menu was covered by the next row
The virtualized task list positions rows with transform (stacking contexts) and wraps them in contain: layout paint. The row dropdown painted under the following row — Delete/Edit clicks were intercepted (and long menus were clipped).
Fix: menu now renders via portal to document.body with a computed position; also added aria-labels ("Star task"/"Task actions") along the way.
MediumWorkspace switcher silently reverted on route refresh
Every server-action refresh re-ran the workspace provider, which unconditionally overwrote the active workspace with the default (first) one — so switching to Syntaxure Labs and then creating a task snapped you back to Personal.
Fix: the provider now preserves the user's selection when it is still valid, falling back only when it isn't.
MediumConfirmDialog rendered inline (despite claiming a portal)
The shared dialog's docstring says "Renders via a portal" — it didn't. Inside the virtualized list it inherited the rows' stacking context, so later rows intercepted the confirm button, and the dialog's title slid behind the sticky toolbar.
Fix: dialog content is now actually portaled to document.body — correct everywhere it's used.

CI Wiring

  • New e2e job in .github/workflows/ci.yml: installs, builds prism-manage, installs Chromium (--with-deps), runs the suite against next start, uploads reports/traces on failure. Gated by detect-changes so it only runs for prism-manage-affecting PRs.
  • ci-status now also gates on the e2e job (failure blocks; skip is fine — forks without secrets stay green).
  • Optional repo secrets E2E_TEST_EMAIL / E2E_TEST_PASSWORD override the defaults; Supabase URL/keys reuse the existing CI secrets.
  • Local: pnpm --filter prism-manage run test:e2e (dev server auto-starts; reuseExistingServer if one is already up).
