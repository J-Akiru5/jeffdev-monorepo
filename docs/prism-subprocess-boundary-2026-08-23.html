The engine moves out of process: AGPL boundary + ReDoS kill switch

docs/prism-subprocess-boundary-2026-08-23.html - branch feat/prism-subprocess-boundary - merged to develop @ 101aef4

Summary. The sandbox preview no longer imports the rule engine in-process. It now spawns @prism-engine/cli sandbox-eval as a memory-capped child process speaking a versioned JSON stdio contract, closing the AGPL copyleft exposure ahead of relicensing and turning the worst-case regex denial-of-service from "hang the server forever" into "SIGTERM at 5s, SIGKILL at 6s, structured 504 to the caller." Defense in depth starts earlier: every user-supplied pattern passes a dual-layer safety gate (internal nested-quantifier fast-reject + safe-regex star-height analysis) and is rejected with reasons before any child spawns. All four required test scenarios pass against the real built CLI - including a hard-kill proof where a stubborn child records its pid, ignores SIGTERM, and is verified dead by pid afterwards. The ./rules public export is retained, and the packed tarball was cold-install re-verified end to end.

01Stdio contract v1 (public surface on @prism-engine/cli)

Command : npx @prism-engine/cli sandbox-eval
stdin   : {"v":1,
           "rulesJson":"<full rules.json v1 envelope, stringified>",
           "files":[{"path":"app/Bad.tsx","content":"..."}, ...]}
          limits mirror the HTTP route: 20 files x 64KB, rulesJson 256KB

stdout  : {"v":1,"ok":true,
           "result":{"ruleCount":n,"filesScanned":n,
                     "findings":[{file,line,severity,ruleId,message,
                                  offending,replacement?}],
                     "summary":{"blocks":n,"warns":n}}}

stderr  : {"v":1,"ok":false,
           "error":{"code":"INPUT_MALFORMED"|"INPUT_INVALID"|
                              "INVALID_RULES"|"EVAL_ERROR",
                    "message":"human readable"}}
exit    : 0 on success | 3 on any error (NEVER 2 - that is the Pass hook
          blocking contract and must stay unambiguous)

RulesParseError inside the evaluator maps to code INVALID_RULES specifically so callers can distinguish "your rules file is bad" (422-class) from internal crashes (500-class).

02Caller side (apps/prism-engine/src/lib/sandbox.ts)

  • Front door: collectUserPatterns() walks the parsed envelope for every pattern/matchPattern string; each passes dual-layer validation. First rejection throws SandboxRejectedPatternError with pattern + reasons - nothing is spawned.
  • Spawn: process.execPath with --max-old-space-size=256 running the resolved CLI entry (createRequire resolution, PRISM_SANDBOX_CLI_ENTRY override hatch for tests/ops). Hard timer: SIGTERM at SANDBOX_TIMEOUT_MS (default 5000, declared in turbo globalEnv), SIGKILL grace window after 1s.
  • Mapping: stderr error envelopes route INVALID_RULES to the legacy SandboxValidationError surface (route 422 unchanged); TIMEOUT -> 504; malformed stdout/child crash -> clean 500 via logError. Response SUCCESS shape is byte-compatible with the old in-process result.
  • Runtime pinning: next.config outputFileTracingIncludes pins node_modules/@prism-engine/** into the sandbox route lambda so the spawned entry exists on Vercel even though the app no longer imports the package statically.

03Timeout-kill PROOF (test output shape)

Stub child: records own pid to PID_FILE, ignores SIGTERM, idles forever.
runSandbox(timeoutMs: 300)

assertions:
  caught instanceof SandboxSpawnError      -> true
  code === "TIMEOUT"                       -> true
  elapsed < 2500ms                         -> true   (SIGTERM 300ms + 1s grace)
  PID_FILE exists                          -> true   (child RAN)
  process.kill(childPid, 0) throws ESRCH   -> true   (child is DEAD)

The pid-death assertion is the platform-neutral proof of an actual kill - signal-delivery markers are meaningless on Windows where cross-process kills are uncatchable TerminateProcess calls.
