05The publish itself — including what fought back

  • EOTP. First npm publish failed with code EOTP: Jeff's account requires interactive 2FA on publishes.
  • Redacted auth URL. The web-auth URL prints as *** whenever npm isn't attached to a real terminal — captured output and even npm's own debug logs are redacted, so the URL cannot be relayed through a tool session. Documented here so nobody burns an hour rediscovering this.
  • Resolution. The publish was relaunched in its own visible console window on Jeff's desktop (Start-Process npm.cmd publish with working directory preset). That window is a real TTY: it printed the full npmjs.com/auth/cli/… URL, Jeff approved in-browser, and the window completed the publish. Registry polling confirmed the flip within seconds of approval.
For next time: this account now publishes via interactive browser OTP from a real terminal only. If CI publishing is wanted post-demo, use a granular access token in GitHub secrets plus a proper publish step — but expect npm's 2026 policy shifts around 2FA-bypassing tokens to need testing, not assuming.
