Summary

The task list now pages instead of capping (keyset pagination, 50 rows per page, "Load more"), the kanban board gained a touch- and keyboard-friendly "Move" menu (drag was the only way before — broken on touch), the task sheet reuses a members cache instead of re-fetching on every open, and two heavy widgets (assistant, tour) are code-split out of the shared bundle. And the new 55-task E2E seed exposed a real virtualizer bug: with more than 20 tasks the list rendered zero rows — fixed.

The Bug H5 Caught

HighTask list rendered zero rows beyond 20 tasks
The virtualized container used contain: strict once a list exceeded 20 tasks — which includes size containment. With no explicit height, the container collapsed to 0px, so the virtualizer "saw" no viewport and rendered nothing. Group headers, counts and the add-input still showed; the rows simply vanished. Invisible in every previous test because no list ever had more than ~20 tasks.
Fix: contain: layout paint — keeps the performance isolation without collapsing the box. Proven by the new pagination E2E (55 seeded tasks render and page correctly).
