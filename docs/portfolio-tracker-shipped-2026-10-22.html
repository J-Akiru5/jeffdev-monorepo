Architecture decisions (as approved)

  • One source of truth: the shared projects table was extended (additive columns) instead of forking a new table — the public /work case studies and the tracker now read the same rows.
  • Additive migration only: 9 columns + 4 guarded CHECKs + 4 indexes; three new tables (partners, project_partners, project_members); a backfill aligns pre-existing rows by their public status. Applied live; generated types regenerated (drift in sync).
  • RBAC: members view everything; founders edit; assigned members update progress/milestones. Budget and retainer amounts are redacted server-side for non-founders — MRR disappears with them. RLS: signed-in read, service-role writes through server actions.
  • Retainers: inline fields (status, monthly, currency, started, renews) — enough for the maintenance badge, Active MRR and renewal awareness; a billing ledger can link to invoices later without rework.
  • Task link: each project can point at one task list (pm_project_id); the detail shows open/completed counts.

Known gaps / next

  • Client clearing — setting a client is supported (name resolves/creates a clients row); explicitly removing one needs a dedicated control.
  • Publishing — the public-site publish flag remains an explicit toggle; the tracker never unpublishes. Publishing stays in the paused prism-admin for now.
  • prism-admin drift — its agency pages have broken columns (dropped client_name, wrong insert shapes). Not touched; the tracker does not depend on them.
  • milestones table conflict — project-scoped vs workspace-scoped definitions; the tracker uses project milestones. prism-manage Operations milestones should be verified separately.
  • Notifications — assignment notifications are wired on the server; no digest/email fan-out yet.
