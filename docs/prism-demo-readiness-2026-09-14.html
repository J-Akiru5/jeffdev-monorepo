9 · Provider trace — does the CLI hard-code an LLM? (Step 4)

Answer: no. The CLI's demo path makes no model call at all; the cloud AI layer is provider-pluggable; there is no hard-coded OpenAI endpoint.

PathWhat it doesCitation
prism check / hook Deterministic regex rule engine. No network, no AI. packages/prism-context-engine/src/commands/check.ts:83–197
prism init Local filesystem scan → rules. "Zero network, zero account." Package deps contain no AI SDK (MCP SDK, commander, chalk, ora only). src/commands/init.ts:4,39–48; package.json:57–62
prism generate CLI itself does no inference; POSTs /api/generate to Prism Cloud (base URL configurable via PRISM_API_URL/config). src/commands/generate.ts:31; src/api.ts:8–16
MCP server AI (optional ranking) Default provider Gemini; Azure only when selected. Embedding failure falls back to priority/keyword sort, so tools still respond without any AI provider. apps/prism-mcp-server/src/lib/ai-router.ts:12–33; src/index.ts:994–1007
Engine AI router (cloud) Provider chain: opencode → deepseek (defaults), or explicit AI_PROVIDER azure/gemini. opencode and deepseek both accept OpenAI-compatible base URLs (OPENCODE_BASE_URL, DEEPSEEK_ENDPOINT). apps/prism-engine/src/lib/ai-router.ts:4,11–16,45–75; opencode.ts:16–18; deepseek.ts:9–21
Honest framing for a local-LLM audience: "The governance layer never calls a model — it enforces rules deterministically and serves context over MCP, so it sits in front of whatever model your client runs. Our AI-completion features route through configurable providers, but we have not yet tested a fully local inference server end-to-end." That is defensible tonight. "Drop-in in front of a local LLM" as a tested integration claim is not.
