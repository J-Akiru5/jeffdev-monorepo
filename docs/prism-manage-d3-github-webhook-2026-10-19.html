D3 — GitHub Webhook Reverse-Sync

2026-10-19 Branch: feat/pm-d3-github-webhook → PR → develop Complete

Summary

Closing or reopening a linked GitHub issue now updates the task automatically: issues.closed → approved, issues.reopened → backlog. The endpoint is HMAC-verified (x-hub-signature-256, constant-time compare) and fails closed when the secret is unset.

What Changed

PieceDetail
lib/github-webhook.tsPure mapper (action → status) + constant-time signature verifier. 5 unit tests (valid/tampered/wrong-secret/missing/malformed).
api/github/webhook/route.tsVerifies the signature, ignores non-issue events (ping → pong), finds the task by github_issue_number, updates status, logs every sync. Unset secret → 503 (disabled); bad signature → 401.
e2e/api.spec.tsUnsigned webhook calls are rejected (401/503).
.env.exampleGITHUB_WEBHOOK_SECRET documented.

Wiring It Up (for the owner — 2 minutes)

GitHub repo → Settings → Webhooks → Add webhook
  Payload URL:  https://manage.syntaxure.dev/api/github/webhook
  Content type: application/json
  Secret:       (the GITHUB_WEBHOOK_SECRET you set on Vercel)
  Events:       Issues  ✓
Then: set GITHUB_WEBHOOK_SECRET on Vercel (any random string, same value).

Notes

  • The webhook deliberately bypasses the approval RBAC — closing the issue on GitHub is the authoritative act, and the task↔issue link is created by a workspace member (the forward sync).
  • Label/assignee reverse-mapping is deferred (login→user mapping needs a directory link); closed/reopened covers the daily loop.
