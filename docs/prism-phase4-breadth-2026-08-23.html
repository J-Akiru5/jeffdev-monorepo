03New check types (additive, tested)

{"type":"naming_pattern","pattern":"^[A-Z][A-Za-z0-9]*$"}

// file_placement - matched files must live under directory
{"type":"file_placement","matchPattern":"^use[A-Z]","directory":"src/hooks"}

// required_import - every covered file must import the specifier
{"type":"required_import","specifier":"@/lib/safe-fetch"}
  • Additive type values only - zero changes to existing four types or any top-level field. v1 schema intact.

Python / Go verdict (your step 6 question)

Nearly free, but not through extraction. They have no design-token concept, so only naming_pattern and file_placement apply - and both are pure PATH checks that already work on ANY extension today: a user can hand-write {"extensions":[".py"],"check":{"type":"naming_pattern",...}} right now and it enforces correctly. required_import as built does NOT cover Python/Go import syntax (unquoted imports), which would be a per-language matcher extension later. Verdict: zero engine code needed; this is documentation + optionally widening DEFAULT_EXTENSIONS guidance, not extractor work.
