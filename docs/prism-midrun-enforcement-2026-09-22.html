2 · How it works

  • PreToolUse. Write → checks tool_input.content without touching disk. Edit → reads the file and applies old_string → new_string in memory. MultiEdit → applies edits[] in order. The deterministic engine runs first; the semantic layer only if regex is clean (same order as before). Any ambiguity (missing payload content, old_string not found, unreadable base file) fails open and logs SKIPPED <reason>.
  • PostToolUse. Unchanged safety net: re-checks the file on disk after the write and returns the same correction if the write already landed.
  • Stop. Derives the session's edited files from transcript_path; if none can be derived, scans the source dir (PRISM_STOP_SCAN_DIR override, 500-file cap). Deterministic-only — one Gemini call per changed file could exceed the hook ceiling. Any remaining block exits 2 with the standard per-file correction. If stop_hook_active is true, it never blocks again (loop guard).
  • Activity log. .prism/activity.log, one tab-separated line per invocation: 2026-09-22T03:18:55Z  pre  <path>  BLOCKED <rule-id>. Results are CLEAN, BLOCKED …, or SKIPPED <reason>. Logging failures are swallowed and never change the exit code.
  • Kill switches. PRISM_DISABLE=1 wins everywhere; semantic additionally requires PRISM_GEMINI_CHECK=1 + a key.

6 · Known limits & Demo-Day risks

Gemini quota is the main demo risk. The demo key is on the free tier: generate_content_free_tier_requests limit 20 for gemini-3.6-flash. Under repeated checks the API returns 429, the semantic layer fails open, and a semantic violation can silently pass as CLEAN in the log. Observed live during testing (503s too). Mitigations now in code: temperature: 0 (stable verdicts) and one retry on 5xx/network within the same timeout. 429 is intentionally not retried. Recommendation: use a billed key or a raised-quota key for Demo Day, and budget the number of semantic checks in the script.
  • Stop gate is deterministic-only. Semantic checks per changed file could exceed the hook timeout; the Stop gate therefore cannot catch intent-level violations — only the deterministic engine.
  • Transcript parsing is best-effort. Unknown/malformed transcript shapes degrade to the source-dir fallback, which is capped at 500 files and skips node_modules/dot-dirs.
  • Bash is not covered. Claude Code's known PreToolUse/Bash issue was not re-tested; enforcement is for Write/Edit/MultiEdit.
  • MultiEdit not live-exercised (not exposed in the test run); its extraction is unit-tested.
  • Fail-open everywhere remains the contract: a hook failure can never block work, by design.
  • Correction format and PostToolUse bytes unchanged — the published, demo-verified contract is intact.
