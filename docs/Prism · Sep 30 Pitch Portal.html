Pitch script

The story, slide by slide

An eleven-slide pitch built around one transformation: from an agent that drifts and a human who cleans up, to an agent that is stopped at the moment of the mistake and corrects itself. Every number on a slide is labeled with what it is. The live demo is the centre of gravity.

PRODUCT

Prism is an active governance layer for AI coding agents. It enforces your project's rules at the moment the agent writes, blocking non-compliant changes before they reach the codebase.

COMPANY

Syntaxure Labs pairs a software services business with its own developer infrastructure: client work funds the company and supplies the real agent failures Prism is built to stop.

Motto, used once at the close: "Governance over Generation."

The transformation

This pair of diagrams is slide 3's content in its simplest form. Today, rules live in instruction files that the agent may or may not follow; violations land on disk and a person has to find them, which costs another round-trip. With Prism, the rule is checked at the tool-call boundary. A violating write never lands; the agent receives the reason and fixes it in the same turn.

Speaker notes

Notes for the slides where wording matters most. Say them in your own voice; the point is what to claim and what to leave out.

Slide 2 — Problem

"AI coding agents are fast, but they don't reliably follow a project's rules. A rules file is advice: the agent may read it, misapply it, or lose it as the context fills. So a person ends up reviewing every change. In one of our own trials, we played the reviewer and told the agent it had broken a design rule. It refused, said no such rule existed, and the violation stayed in the code."

Slide 3 — Solution

"Prism doesn't ask the agent to behave. It sits where the agent actually writes files. When a write breaks a rule, Prism stops it before it reaches disk and tells the agent why. The agent fixes it in the same turn."

Slide 4 — Demo transition

"Here's the rule on our dashboard. I'll pull it into this project, then ask the agent to do something that breaks it. Watch the log on the right."

Slide 5 — Fail safe

"Security tools that fail silently are worse than none. In strict mode, if Prism isn't running, the agent can't write at all. Every decision, allowed or blocked, is written to an audit log."

Slide 6 — Validation

"Our first paired trial is small, three tasks, so we treat it as direction, not proof. In every task, the governed agent needed one human round-trip instead of two. Token use varied by task, from 40% lower to 28% higher, and we report that range rather than a headline number. A larger pre-registered comparison is running now; results arrive October 4."

Slide 7 — Traction

"We don't have paying Prism customers yet. What we have: the CLI has been downloaded 361 times from npm since January, which is a download count, not a user count. Our services side has delivered client systems. And we placed second at the KWADRA MVP pitch."

Morning-of runbook

  1. Close every OpenCode process (desktop app and any CLI), then relaunch. A process started before the enforcement files changed keeps a stale plugin.
  2. Run the preflight in prism-live-demo. It must print READY, including check 7 (no stale processes).

  4. Run demo-reset.ps1 to restore the source files and start an empty log.

  6. One full rehearsal on the stage model, then reset again.

Q&A war room

Hard questions, honest answers

Answers built only from verified or stated facts. Keep each one under thirty seconds; offer detail rather than volunteering it.

Product

What exactly does Prism intercept?
File writes and edits made through the agent's own write and edit tools. Before the write happens, Prism checks the proposed content against the project's rules and either allows it or blocks it with a reason.
What kinds of rules can it enforce?
Forbidden patterns, required design tokens, banned arbitrary values, banned imports and file placement rules, from a rules file you define or pull from the dashboard.
Does Prism use AI?
The core is deterministic: it doesn't guess. An optional semantic layer uses an AI model to catch intent-level violations a pattern can't express. It's off by default, and if it fails it steps aside rather than blocking by mistake.
What happens if Prism crashes?
By default it fails open, so work isn't blocked by a bug. In strict mode it fails closed: if Prism can't run, the agent can't write. Every decision is logged either way.

Competition

Isn't this just CLAUDE.md or a rules file?
A rules file is advice the agent reads. Prism is enforcement at the point of writing: it doesn't ask the agent to behave, it stops the write. In our own trial, an agent refused a correction; a blocked write can't be argued with.
Why not write a 100-line hook myself?
You can, for one pattern in one agent. Prism gives you one rule set across agents (verified on Claude Code and OpenCode), a dashboard to manage and share rules, fail-closed mode, an audit log, and a tested engine.
Why can't Anthropic or Cursor build this?
They could, for their own agent. Our position is vendor-neutral: one set of rules governing whichever agents a team uses. We don't claim they can't build it.
Isn't this just middleware?
Architecturally, yes: it sits in the middle, which is the point. The value is in the rules, the adapters for each agent, and the team workflow around them.

Technical & security

Can the agent get around Prism?
Yes, one way today: writing a file through a shell command instead of the edit tool isn't checked yet. We know it, we log what we can, and closing it is on the roadmap.
Does it handle multi-file edits?
Multi-edit and patch formats are handled and unit-tested, but not yet verified live. We don't claim them.
What about multiple agents at once?
Subagents inside one OpenCode session are covered; we tested it. Coordinating separate parallel agents isn't a feature yet.
Does Prism see our source code?
The check runs locally, on your machine, inside the agent's hook. Rules come from your project file or dashboard; the log stays local. The optional semantic check sends the proposed change to an AI provider, and it's off by default.
Can it be self-hosted?
The CLI and rule engine are open source and run locally today. A self-hosted dashboard isn't offered yet.
Which agents does it support?
Verified live: OpenCode and Claude Code. Configuration exists for Cursor; we haven't verified it live, so we don't claim it.
