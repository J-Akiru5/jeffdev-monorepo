01 — Position

Fixing "another Claude"

A developer with Claude already has an agent that writes decent code. Prism, presented as a paid subscription with "AI Generations" as a headline dashboard metric, reads as a second AI tool competing for the same budget line. That objection is a positioning failure, not a price objection — and dropping the price alone wouldn't have fixed it.

Claude makes one agent write well. Prism makes every agent write your way — and keeps doing it when there are five of you.

The structural fix follows from one fact: the Pass costs Syntaxure nothing to run. It's regex executing on the user's own machine. Gating a zero-marginal-cost feature behind a subscription is the worst possible trade — it maximises friction and captures nothing. Give it away, and "there's nothing to buy" answers the objection before it's raised.

What genuinely costs money is inference, hosting, and sync. Those get priced. And because the AI layer runs on OpenCode free models, even that cost stays near zero — which means the free tier can be generous rather than defensive.

Sequencing: solo devs now, enterprise later

The first users are new-generation agentic developers — people whose workflow is already agent-first and who haven't ossified around a senior dev's habits. They will not pay, and that's correct: they're the distribution, not the revenue. Free local CLI and TUI, open source, no account required.

Revenue comes later from corporates and BPOs, with DOST-ASTI credibility as the bridge. That ordering means the break-even model needs revisiting — 46 subscribers at $18 was a different business than this one. Enterprise seats and on-prem licences are the line that actually closes the gap, and the solo tier's job is to make those conversations warm.

Honest tension

Free-forever local slows monetisation and pushes break-even out. That's a real cost, accepted deliberately in exchange for adoption and the open-source position. Worth restating plainly to KWADRA rather than presenting the old 46-subscriber model as though nothing changed — a founder who revises a model with reasoning reads stronger than one who doesn't notice it broke.

Phase 0 — Wednesday only

Three days. The correction loop works, is published, and is rehearsed headlessly. Two things are demo-visible and worth fixing; a third is the last real risk.

  • Tier cap. The dashboard shows 2/1 projects on Free with a red overflow bar. Anyone glancing at the screen sees a system not enforcing its own rules.
  • Upgrade dead-end. If someone clicks Upgrade during the demo and nothing happens, that's the moment they remember. Either wire it or make it say "coming soon" honestly.
  • Interactive rehearsal. Every run so far has been headless. Headless and interactive Claude Code sessions can surface output differently, and you're presenting the interactive one.

"Generate Skill — Coming Soon" stays. At a check-in it reads as roadmap, not gap.

Phase 2 — Pricing & payments

Implement the model above. Free tier genuinely unlimited locally; paid tiers enforced by the Phase 1 machinery. Regional pricing by detected locale with a manual override. Upgrade flow actually reaching PayPal checkout and returning to a correct subscription state.

PayPal only — PayMaya and GCash are a later addition once the model is settled and the existing integration is verified. Adding a second payment rail while the first one has an unverified webhook would be compounding a problem.

Phase 3 — OpenCode AI layer

One shared client for all AI features: auto model selection defaulting to MIMO, free models prioritised, image input supported. Three consumers:

  • Rules creator — describe a convention in plain language, get a rule with a working check block. This is the highest-value AI feature because authoring check blocks by hand is the main friction in the Kitchen.
  • Skills creator — replaces the current "Coming Soon" screen. Describe a workflow, get a procedural guide for agents.
  • Sandbox preview — run a constitution against sample code and see what would be caught, before deploying it. Tier-limited by run count.
Why this is cheap

Free models via OpenCode means the AI layer's marginal cost is near zero. That's what makes a generous free tier viable, and it's why the AI features can be a Pro differentiator without becoming a cost centre.

Phase 4 — Breadth

Today Prism enforces TypeScript, JSX, and Tailwind. A broad user base needs more: Vue and Svelte, plain CSS and SCSS, Python and Go for non-frontend conventions, and check types beyond the current four — naming patterns, file placement, required imports.

Also: Cursor and Windsurf hook formatters behind the existing --format flag. The generic naming was chosen for exactly this, so it should be additive rather than structural.

Phase 5 — Open source + launch

Licence the CLI and rule engine, write CONTRIBUTING and a real README, audit history before promoting the repo. Ship the TUI as the free tier's local Kitchen. Rewrite the docs app — it currently leads with video-to-context extraction, which is deprecated. Replace hardcoded monitoring with real Sentry coverage across the ~53 unhandled console.error sites.

03 — Orchestration

Three agents, zero collisions

The split is by file domain, not by task type. Each agent owns directories the others never touch, so parallel work can't produce a merge conflict.

AgentOwnsNever touchesWorkspace
Ox Backendapps/prism-engine/src/app/api/**, src/lib/**, packages/prism-context-engine/**, Supabase migrationsDashboard UI, docs appMain worktree, feat/prism-*
Claude Code Frontendapps/prism-engine/src/app/(dashboard)/**, components, pricing page, upgrade flow, TUIAPI routes, lib, migrationsSeparate worktree, feat/prism-ui-*
Copilot Docsapps/prism-docs/**Everything elseCloud, PR to main
The worktree rule

Two agents in the same directory is a race, not parallelism. Before starting Claude Code alongside Ox, create a separate checkout: git worktree add ../prism-ui feat/prism-ui-pricing. Point the second IDE there. One branch each, merged to develop separately.

All three merge to develop, never to main directly. main is promotion-only, and it triggers a production Vercel deploy — so a merge to main during a build week should be a deliberate act with a rehearsal behind it, not a routine step.

04 — Open questions

Still undecided

  • Which PayPal webhook is registered? Cannot be answered from the repo — check the PayPal dashboard. Until known, subscription state is not trustworthy.
  • Break-even model revision. The 46-subscriber figure assumed a different pricing structure. Needs recalculating before the next KWADRA financial conversation.
  • Open-source licence choice. MIT maximises adoption; AGPL prevents a competitor hosting your engine as a service. Given the enterprise/on-prem plan, worth thinking about rather than defaulting.
  • Start Media 60/40. Still no written MOU, and it now touches an open-source decision — worth confirming what the arrangement covers before the CLI is licensed publicly.
  • TUI scope. A local Kitchen (browse constitution, live violation feed) or just a nicer init? Different builds.
