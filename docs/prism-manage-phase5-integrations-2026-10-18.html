Summary

Work now flows out of prism-manage: any task can spawn a labeled GitHub issue in one click (linked back to the task), and task status changes push to that issue — approved tasks close it. Slack posts assignments and comments with deep links when SLACK_WEBHOOK_URL is set. Everything is best-effort: GitHub/Slack being down never blocks task work. No migration required — the task↔issue link lives in the existing tasks.github_issue_number column.

Decisions & Checkpoints

Decision: who can create issues from tasks?
Any member who can see the task (RLS proves access) — the existing marketing gate was kept only for the marketing pipeline. Task→issue is now a general work integration, not a marketing-campaign action.
Decision: Slack config model
Single env webhook (SLACK_WEBHOOK_URL) — zero schema changes, works immediately for the team. Per-workspace webhook config is a future enhancement (needs a workspace-settings column).
Deferred: email digest
