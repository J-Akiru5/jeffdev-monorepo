Decisions & Checkpoints

Decision: app-side notification fan-out vs DB triggers
App-side. notifications is owner-read-only by RLS — a member can't insert rows for teammates. Server actions fan out via the service-role client (same pattern as audit_logs), which keeps dedup + mention-resolution logic in TypeScript. All write paths go through server actions, so no trigger is needed. The existing CPO review trigger stays as-is.
Decision: reading other members' names/avatars for comments
Two-step read. The task is first fetched through the user's RLS-scoped client (proving access); only then does the admin client read comment author profiles and audit rows. No bypass of task visibility.
Realtime: publication changes are guarded
The migration adds each table to supabase_realtime only if not already present (pg_publication_tables check), so re-running is safe and it can't error on tables Supabase already publishes.
