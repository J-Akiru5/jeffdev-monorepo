Bugs Found & Fixed

🔴 $0 displayed on all service pages instead of prices

Root cause: parseAmount("PHP 150,000") — regex [₱$,\s] stripped symbols but not the letters "PHP". Result → NaN → shows $0.

Fix: Added .replace(/^PHP/i, "") in price-display.tsx.

🔴 Supabase price_min = 0 not showing "Custom quote"

Root cause: Filter .filter(svc => svc.price_min && svc.price_min > 0) treated 0 as falsy and filtered it out.

Fix: Changed to .filter(svc => svc.price_min !== null && svc.price_min !== undefined) in lib/data.ts. Now 0 → "Custom quote", null → fall through to hardcoded.

🔴 Currency flash from $ to ₱ on page load

Root cause: Old CurrencyProvider initialized with hardcoded "USD", then useEffect read cookie and flipped it client-side.

Fix: Moved currency detection to server-side detectCurrency() in layout.tsx. Pass initialCurrency prop. No flash.

🟡 Quote form was for SaaS templates, not custom services

Root cause: Form was built for product_templates (SaaS template products with monthly pricing). Your business is custom development.

Fix: Complete rewrite — removed template selection, added project type / scope / budget / timeline.

🟡 Geo-IP currency detection via proxy.ts didn't work

Root cause: Sub-requests (JS/CSS) overwrote the currency cookie set by the main request.

Fix: Moved geo detection to server-side layout. Vercel geo header + Accept-Language fallback. No cookie overwrite issues.

🟡 CurrencyOverride infinite reload loop

Root cause: window.location.reload() reloads the same URL (with ?currency=USD), causing an infinite loop.

Fix: Added cookie-match check before reloading: if (currentCookie === currency) return;

🟡 pnpm 9 deprecation warning

Root cause: pnpm.neverBuiltDependencies in package.json is no longer read by pnpm 9.

Fix: Moved to .npmrc as never-built-dependencies[]=unrs-resolver.

What Was Replaced & Why

SaaS Template Quote → Custom Project Quote

Before: "Select Your Base Template" — asked clients to pick from SaaS templates with monthly pricing.

After: "What do you need built?" — Website / SaaS / AI / Cloud / Other. Matches your actual services.

Why: Clients were confused. You don't sell templates — you build custom.

3-Step Form → Dynamic 2 or 3 Steps

Before: Always 3 steps: Template → Scope → Contact

After: 2 steps if service preselected (Scope → Contact), 3 steps if direct visit (Project → Scope → Contact)

Why: Less friction. Clients coming from a service page don't need to re-select the service.

Template Customization Scope → Project Scope

Before: "Basic Brand/UI Tweaks", "Custom API Integrations" — assumed template customization

After: "New Project", "Redesign", "Feature Addition", "Full Custom Build" — clear project types

Why: Template scope options made no sense for custom builds.

Added Budget Range (Optional)

Before: No budget field — client had no way to indicate investment range

After: Optional budget chips from ₱50K to ₱500K+

Why: Provides lead qualification data. Complements starting prices on service pages.

Added Timeline

Before: No timeline field — didn't know if client needed it in 2 weeks or 6 months

After: ASAP / 1-3mo / 3-6mo / Flexible

Why: Helps you plan capacity and prioritize leads.

Proxy Middleware → Server-Side Layout

Before: proxy.ts handled both admin routing AND geo-IP currency detection — unreliable

After: proxy.ts is admin-only. currency detection in server-side layout.tsx

Why: No flash, no cookie overwrite issues, cleaner architecture.

Hardcoded "USD" → Server-Side Detection

Before: CurrencyProvider initialized with "USD", flipped client-side (flash)

After: Layout detects currency via Vercel geo + Accept-Language, passes correct value from SSR

Why: Zero flash. 2026 industry standard: detect server-side, render correctly from first byte.

Service Prices Updated

Before: ₱75K / ₱150K / ₱50K — too cheap, hurt trust

After: ₱150K / ₱250K / ₱80K — market-aligned for a professional agency

Why: Too-low prices signal low quality. Build trust with fair market pricing.
