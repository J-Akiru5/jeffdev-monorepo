Decisions & Checkpoints

Decision: client-side vs server-side search on the tasks page
Both, split by role. The tasks page filters the already-loaded workspace tasks instantly (zero latency); the palette uses the server-side searchWorkspace action because it must search beyond the visible list (pages too). RLS scopes every query.
Decision: modifying shared @syntaxure/ui in an app phase
The palette needed a data-search hook. The change is one optional prop with a no-op default — other apps compile and behave identically (verified: UI package check-types + lint with --max-warnings 0).
Safety: user input in PostgREST filter strings
The palette search builds an .or() filter; input is sanitized (wildcards, commas, parens, quotes stripped, 80-char cap) and RLS remains the real boundary. Pages search uses a bound ilike parameter — no string building at all.
