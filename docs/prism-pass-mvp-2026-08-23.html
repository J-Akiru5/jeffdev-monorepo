The Pass. Local rule enforcement, closed loop.

branch feat/prism-pass → develop · prism-context-engine 1.1.2 → 1.2.0 · unpublished
The Pass turns Prism from a rule delivery system into a rule enforcement system. A Claude Code PostToolUse hook runs the new regex-based engine (prism check --hook) against every file an agent writes; any block-severity violation exits 2 and feeds a precise correction — file, line, exact offending value, exact replacement — back into the agent's context, and the agent fixes itself on its own next turn. Both delivery mechanisms were spike-verified against the installed Claude Code v2.1.175 before any production code was written, and the full Wednesday demo was rehearsed end-to-end headlessly: the agent wrote a banner violating four rules and self-corrected every blocking one without a single human turn.

01Spike — verified before building

Mandated gate: prove a hook message actually reaches the agent's context and drives unprompted self-correction, using the installed Claude Code (v2.1.175), not documented behaviour. Two throwaway projects, forced violations, headless runs with full transcript capture:

MechanismResultEvidence
exit 2 + stderrPASSWrite blocked → agent's immediate next action was an Edit replacing #3B82F6 with var(--brand-primary); agent later quotes the hook message verbatim ("per the hook's design-token instruction")
exit 0 + JSON {decision:"block",reason}PASSIdentical loop, second run: Write blocked → unprompted Edit at +8s

Chosen: exit 2 + stderr. Simplest contract, no stdout-schema drift risk across CC versions, and fail-open falls out naturally (anything ≠ 2 passes through). The formatter stays swappable per your generic-format requirement.

02.prism/rules.json — the v1 contract

This is the schema tomorrow's dashboard endpoint generates against. Versioned envelope, optional check makes a rule machine-enforceable; rules without it remain advisory and flow through the MCP path unchanged.

{
  "version": 1,
  "rules": [
    {
      "id": "styling/brand-color-tokens",       // required, unique, "<category>/<name>"
      "category": "styling",                    // architecture | styling | security | testing
      "severity": "block",                      // block | warn — omitted defaults to "warn"
      "instruction": "Brand colors must reference their CSS variable tokens.",
      "extensions": [".tsx", ".css"],           // OPTIONAL fast-path gate; default = common code extensions
      "check": {                                // OPTIONAL — absence = advisory-only rule
        "type": "forbidden_pattern",
        "pattern": "#[0-9a-fA-F]{6}\\b",         // JS regex source (validated at parse time)
        "flags": "",                            // optional regex flags ("g" appended automatically)
        "allowlist": ["#FFFFFF"],               // optional literal exceptions, case-insensitive
        "fix": "var(--brand-primary)",          // optional exact replacement shown to the agent
        "message": "Use the design token."
      }
    },
    {
      "check": {
        "type": "required_token",
        "tokenSet": "brand-colors",
        "tokenMap": {                           // raw value -> exact token replacement;
          "#06b6d4": "var(--brand-primary)"     // matched case-insensitively; dashboard generates this
        },                                      // mechanically from the token store
        "message": "Use the brand token."
      }
    },
    {
      "check": {
        "type": "banned_import",
        "specifiers": ["lodash", "@/lib/legacy-db"]   // bare package names also match subpaths (/fp, /prism);
      }                                              // matches import / export-from / require() / dynamic import()
    },
    {
      "check": {
        "type": "arbitrary_value",
        "properties": ["w", "max-w", "h", "text", "p", "gap"]   // Tailwind props scanned for -[...] values
      }
    }
  ]
}
Additive field you approved indirectly: optional per-rule extensions. It exists solely to honour your fail-open requirement ("file extension not covered by any rule → exit 0 fast"). Flagged here so the endpoint can choose to emit it or not — everything else is exactly the approved shape.

Fail-open matrix (hook mode)

  • PRISM_DISABLE=1 kill switch — instant exit 0, zero work done
  • rules missing/malformed → warn on stderr, exit 0
  • engine throws / file unreadable → warn on stderr, exit 0
  • extension not covered → silent exit 0, no scan
  • block finding present → the only non-zero path

07Known sharp edges & suggested next steps

  • Catch-all hex rule suggests var(--brand-primary) for unknown colors; nearest-token mapping belongs in the dashboard endpoint's generator.
  • Uppercase token variants (#06B6D4) get caught twice (token rule + catch-all) — same fix, one edit clears both; noted in README.
  • Regex engine by design: AST-class patterns (e.g. "no hooks in conditionals") are out of scope for v1.
  • Next: dashboard endpoint emitting rules.json from the token store (schema above is the contract), then Cursor/Windsurf formatters behind --format.
