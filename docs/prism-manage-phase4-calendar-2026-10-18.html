Summary

The fake "Sync Now" is gone. prism-manage now does real two-way Google Calendar sync: tasks with due dates mirror to Google (timed or all-day, in your timezone), app events push on create/update/delete, Sync Now pulls and reconciles Google events, tokens refresh automatically with rotation, and a daily Vercel cron reconciles every connected user. prism-manage stays authoritative for work items — Google edits to task-mirrored events never overwrite your tasks. No migration required — everything rides on existing columns + user_tokens.metadata.

Decisions & Checkpoints

Decision: where does sync state live?
user_tokens.metadata (JSONB) — last_synced_at + last_sync_error. Zero schema changes: the phase needed no migration at all, answering the open question directly.
Conflict policy (ADR-5): who wins?
prism-manage wins for work items. Pull skips task-mirrored rows entirely — Google edits to them are ignored, external deletions trigger a recreate on the next task save. Google-sourced rows follow Google (updates overwrite; externally deleted rows are swept). Window: -30d .. +90d.
Timezone handling: wall-clock without a tz library
Timed events use { dateTime, timeZone } pairs (Google interprets the wall clock in the given zone); end times are computed with pure UTC arithmetic so no DST/offset math is needed. Zone comes from user_profiles.timezone, defaulting to Asia/Manila.
Trade-off: task writes now include a Google API call
Best-effort and only when a due date exists + Google is connected; the lib never throws and failures record a sync error for visibility. Keeps the "zero silent failures" rule without blocking core task writes on Google availability.
