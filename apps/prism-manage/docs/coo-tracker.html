Database Setup

Create 3 Supabase tables with RLS policies
SQL ▾
What are we doing? We're creating 3 new tables in Supabase (our database) to store milestones, business model canvas data, and infrastructure costs. Think of tables like Excel sheets — each one holds a specific type of data.
Where to run this: Go to supabase.com/dashboard → select your project → click "SQL Editor" in the left sidebar → paste each SQL block and click "Run".
Create the milestones table
This table stores project milestones — things like "Complete MVP", "Launch beta", etc. Each milestone has a status (pending, in progress, completed, blocked) and a due date.
-- Run this in Supabase SQL Editor CREATE TABLE IF NOT EXISTS milestones ( id text PRIMARY KEY, workspace_id text NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE, department_id text REFERENCES departments(id) ON DELETE SET NULL, title text NOT NULL, description text, due_date date, status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'completed', 'blocked')), deliverables text[] DEFAULT '{}', created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now() ); CREATE INDEX idx_milestones_workspace ON milestones(workspace_id); CREATE INDEX idx_milestones_status ON milestones(workspace_id, status); ALTER TABLE milestones ENABLE ROW LEVEL SECURITY; CREATE POLICY "Authenticated can read milestones" ON milestones FOR SELECT USING (auth.role() = 'authenticated'); CREATE POLICY "Founders can insert milestones" ON milestones FOR INSERT WITH CHECK (auth.role() = 'authenticated'); CREATE POLICY "Founders can update milestones" ON milestones FOR UPDATE USING (auth.role() = 'authenticated'); CREATE POLICY "Founders can delete milestones" ON milestones FOR DELETE USING (auth.role() = 'authenticated');

Create the bmc_sections table
This table stores the 9 blocks of the Business Model Canvas. Each block (like "Key Partners" or "Revenue Streams") stores markdown content that the COO can edit.
CREATE TABLE IF NOT EXISTS bmc_sections ( id text PRIMARY KEY, workspace_id text NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE, block text NOT NULL CHECK (block IN ( 'key_partners', 'key_activities', 'key_resources', 'value_propositions', 'customer_relationships', 'channels', 'customer_segments', 'cost_structure', 'revenue_streams' )), content text DEFAULT '', updated_by uuid REFERENCES auth.users(id), updated_at timestamptz NOT NULL DEFAULT now(), UNIQUE(workspace_id, block) ); CREATE INDEX idx_bmc_workspace ON bmc_sections(workspace_id); ALTER TABLE bmc_sections ENABLE ROW LEVEL SECURITY; CREATE POLICY "Authenticated can read BMC" ON bmc_sections FOR SELECT USING (auth.role() = 'authenticated'); CREATE POLICY "Founders can upsert BMC" ON bmc_sections FOR INSERT WITH CHECK (auth.role() = 'authenticated'); CREATE POLICY "Founders can update BMC" ON bmc_sections FOR UPDATE USING (auth.role() = 'authenticated');

Create the infrastructure_costs table
This table tracks monthly costs for services like Vercel, Supabase, OpenAI, etc. The COO enters these manually to monitor budget vs. actual spending.
CREATE TABLE IF NOT EXISTS infrastructure_costs ( id text PRIMARY KEY, workspace_id text NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE, service_name text NOT NULL, category text NOT NULL DEFAULT 'other' CHECK (category IN ( 'hosting', 'database', 'ai_api', 'dev_tools', 'other' )), monthly_budget numeric(10,2) DEFAULT 0, actual_spend numeric(10,2) DEFAULT 0, period text NOT NULL, notes text, created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now() ); CREATE INDEX idx_costs_workspace_period ON infrastructure_costs(workspace_id, period); ALTER TABLE infrastructure_costs ENABLE ROW LEVEL SECURITY; CREATE POLICY "Authenticated can read costs" ON infrastructure_costs FOR SELECT USING (auth.role() = 'authenticated'); CREATE POLICY "Founders can manage costs" ON infrastructure_costs FOR ALL USING (auth.role() = 'authenticated');
SQL

Zod Schemas

Define data shapes and validation rules
TypeScript ▾
What are Zod schemas? They're like blueprints that define what our data looks like. If someone tries to save data that doesn't match the blueprint (like a missing required field), Zod catches the error before it reaches the database. This keeps our data clean and consistent.
Open src/lib/schemas.ts
This is the single source of truth for all data shapes in prism-manage. We'll add our new schemas at the end of the file.

Add at the end of schemas.ts. This defines the milestone data shape: what fields exist, what types they are, and which are required vs optional.
// ────────────────────────────────────────────── // Milestone Schema // ────────────────────────────────────────────── export const MilestoneStatusEnum = z.enum(["pending", "in_progress", "completed", "blocked"]); export type MilestoneStatus = z.infer<typeof MilestoneStatusEnum>; export const MilestoneSchema = z.object({ id: z.string(), workspaceId: z.string(), departmentId: z.string().nullable().optional(), title: z.string().min(1).max(300), description: z.string().optional(), dueDate: z.string().optional(), status: MilestoneStatusEnum.default("pending"), deliverables: z.array(z.string()).default([]), createdAt: z.string(), updatedAt: z.string(), }); export type Milestone = z.infer<typeof MilestoneSchema>; export const CreateMilestoneSchema = MilestoneSchema.omit({ id: true, createdAt: true, updatedAt: true, }); export type CreateMilestoneInput = z.infer<typeof CreateMilestoneSchema>; export const UpdateMilestoneSchema = MilestoneSchema.partial().pick({ title: true, description: true, dueDate: true, status: true, deliverables: true, departmentId: true, }); export type UpdateMilestoneInput = z.infer<typeof UpdateMilestoneSchema>;

Server Actions

TypeScript ▾
What are server actions? They're functions that run on the server (not in the browser). When a user clicks a button or submits a form, the browser calls these functions to create, read, update, or delete data in Supabase. They always start with "use server" at the top.

Business Model Canvas Page

Build the /bmc page with 9-block grid and inline editing
React ▾
What is the Business Model Canvas? It's a strategic management tool created by Alexander Osterwalder. It has 9 building blocks that describe how a business creates, delivers, and captures value. The classic layout is a grid with 9 boxes. Our version renders this grid with editable content in each block.
