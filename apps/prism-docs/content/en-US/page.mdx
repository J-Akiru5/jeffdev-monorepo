# Prism Context Engine

**The Context Governance Layer for AI Coding Assistants** — Stop your AI from hallucinating your architecture. Extract rules from your live site or repo, deliver them to Cursor / Windsurf / VS Code / Claude via MCP, and enforce them on every file save.

## What is Prism Context Engine?

Prism is an **MCP-based governance platform** that:

1. **Extracts rules** from your live website (Playwright URL scan) or local repo — automatically, in under 30 seconds
2. **Stores & ranks rules** in Cosmos DB using Gemini vector embeddings — only relevant rules are sent per task
3. **Delivers rules via MCP** to any IDE (Cursor, Windsurf, VS Code, Claude Desktop) — cross-IDE, write once
4. **Enforces rules** by checking and auto-fixing AI-generated code on every file save

**The measurable outcome:** 64% token reduction (~$55–150 → ~$20–55/dev/month) + consistent, rule-compliant AI output.

### The Core Metaphor

| Concept | Prism Equivalent | Description |
|---------|------------------|-------------|

### Why Prism vs Built-in Alternatives

Cursor has `.cursorrules`, Claude has project knowledge, VS Code has Copilot instructions — each is siloed, manual, and IDE-specific. Prism's advantage:

| Feature | Prism | `.cursorrules` / IDE rules |
|---------|-------|---------------------------|
| Cross-IDE | ✅ Write once, works in 6 IDEs | ❌ One per IDE |
| Smart retrieval | ✅ Vector embeddings — only relevant rules per task | ❌ Dumps everything every time |
| Auto-extraction | ✅ Playwright scans your live URL | ❌ Manual authoring |
| Active enforcement | ✅ `prism_fix` catches violations on save | ❌ Passive suggestions only |

## Architecture

```
Developer scans URL or repo
  ↓
prism connect --url https://yoursite.com
  → Playwright crawls site (depth 2, up to 5 pages)
  → Gemini 3.5 Flash generates 15–25 rules from page content
  → Rules saved to Cosmos DB + ~/.prism/rules.json
  ↓
Developer opens IDE
  ↓
prism init (run once)
  → Auto-detects Cursor / VS Code / Windsurf / Claude Desktop
  → Writes MCP config pointing to: prism serve
  ↓
IDE launches prism serve (automatic on open)
  → Spawns prism-mcp-server --standalone as child process
  → MCP server connects to Cosmos DB
  ↓
AI gets a task
  → Calls get_architectural_rules({ task: "build a button" })
  → Gemini embedding ranks rules by relevance (cosine similarity > 0.72)
  → Returns only relevant rules (target: ~1,800 tokens vs 60,000 without Prism)
  ↓
Developer saves a file
  → VS Code calls prism_check on the generated code
  → Violations highlighted with quick-fix code actions
  → prism_fix auto-corrects the violation
```

## What Makes Prism Different?

### 🌐 URL-First Rule Extraction
Point Prism at your live site. It crawls pages with Playwright, extracts CSS variables, component patterns, spacing tokens, and naming conventions — generating 15–25 rules in under 30 seconds. No manual writing.

### 🧠 Smart Context Selection
Rules are embedded with Gemini (3072-dim vectors). When your AI asks for rules, only the ones relevant to the current task are returned. Sending "build a button" returns button/component rules, not API or testing rules.

### 📦 Context Kitchen
`prism kitchen analyze --task "build a nav"` shows exactly what your AI will receive before it gets it. Preview, trim, and optimize your rule budget.

### 🔒 Active Enforcement
`prism_check` validates AI-generated code against your rules on every save. `prism_fix` applies corrections. VS Code shows violations as diagnostics with quick-fix actions.

### 📊 Telemetry
`prism telemetry` shows your real token usage, cache hit rate, and estimated cost savings per month.
