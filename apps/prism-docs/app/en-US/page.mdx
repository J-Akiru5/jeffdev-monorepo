# Prism Context Engine

A rules layer for AI coding agents. Prism checks every write your agent makes against your team's rules and sends corrections back to the agent.

## What is Prism Context Engine?

AI coding assistants (Cursor, Claude Code, Windsurf, VS Code) write code that often ignores your project's conventions. Prism fixes that with a local rules file and an enforcement hook:

1. **Define rules** — `.prism/rules.json` in your repo. Plain JSON. Types include forbidden patterns, required design tokens, banned imports, and more.
2. **Check every write** — the `prism check` hook runs inside your agent. Violations at `block` severity halt the agent and it corrects itself.
3. **Sync with the dashboard (optional)** — the hosted dashboard at [prism.syntaxure.dev](https://prism.syntaxure.dev) manages projects, rules, and brand profiles. The CLI works without an account.

## Who is it for?

Solo developers and small teams first. Larger teams can share rules through the dashboard and the Team plan (see [Pricing](/pricing)).

## Quick Start (no account required)

```bash
# 1. Install the CLI (Node.js 20 or newer)
npm install -g @prism-engine/cli

# 2. Generate .prism/rules.json from your project's own config
#    and wire the agent hooks
prism init

# 3. Check a file by hand
prism check src/App.tsx
```

`prism init` reads your `package.json`, `globals.css`, and Tailwind config. It makes no network calls.

## How it works

```
┌───────────────────────────────────────────────┐
│  Your AI coding agent (Cursor, Claude Code…)  │
│  writes or edits a file                       │
└──────────────────────┬────────────────────────┘
                       │ hook event (stdin JSON)
                       ▼
┌───────────────────────────────────────────────┐
│  prism check --hook                           │
│  reads .prism/rules.json, checks the content  │
│  exit 2 + correction text on violations       │
└──────────────────────┬────────────────────────┘
                       │
            ┌──────────┴───────────┐
            │ clean                │ violation
            ▼                      ▼
      write proceeds        the agent reads the
                            correction and fixes
                            the file
```

Enforcement is local. Your code never leaves your machine for the check itself.

## Real-world example

```json
// .prism/rules.json (excerpt)
{
  "version": 1,
  "rules": [
    {
      "id": "styling/no-magenta",
      "category": "styling",
      "severity": "block",
      "extensions": [".tsx"],
      "check": {
        "type": "forbidden_pattern",
        "pattern": "#ff00ff",
        "message": "Use the design system palette, not magenta."
      }
    }
  ]
}
```

With this rule in place, the agent cannot write `#ff00ff` into a `.tsx` file. The hook returns a correction and the agent fixes it.
