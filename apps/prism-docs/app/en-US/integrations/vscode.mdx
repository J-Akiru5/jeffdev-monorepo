# VS Code Integration

Prism supports VS Code through `prism ide-setup` and a companion extension.

## Setup with `prism ide-setup`

```bash
prism ide-setup
```

For VS Code, the command updates your user `settings.json` with:

```json
{
  "prism.token": "<your token>"
}
```

Paths it checks:

- Windows: `%APPDATA%/Code/User/settings.json`
- macOS: `~/Library/Application Support/Code/User/settings.json`

If the settings file does not exist, setup skips VS Code and tells you. After setup, the CLI prints a reminder to install the Prism extension from the VS Code marketplace for full support.

## Prism extension

This repository ships a VS Code extension at `extensions/prism-vscode` (publisher `prism-engine`, version 1.1.0). It adds Prism commands (Connect / Disconnect) and reads the `prism.token` setting or the `PRISM_TOKEN` environment variable.

## MCP support

VS Code works with MCP through the community MCP extension. `prism ide-setup` writes the token setting; the MCP server command is:

```json
{
  "mcpServers": {
    "prism": {
      "command": "npx",
      "args": ["@prism-engine/cli", "serve"],
      "env": { "PRISM_TOKEN": "<your token>" }
    }
  }
}
```

## Rules without MCP

For any editor, the local rules file works with no server at all:

```bash
prism init
prism check src/App.tsx
```

`.prism/rules.json` and `prism check` do not require VS Code, an account, or the network.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `prism.token` not written | The VS Code user settings file was missing; create it or rerun `prism ide-setup` |
| Extension not working | Check `PRISM_TOKEN` or the `prism.token` setting; restart VS Code |
| Hook not applicable | Hook enforcement is not wired for VS Code; use `prism check` manually or MCP advisory rules |
