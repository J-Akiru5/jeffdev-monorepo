# API Reference

The dashboard exposes a REST API under `/api/v1`. Use it to manage projects, rules, brands, and keys programmatically.

## Base URL

```
https://prism.syntaxure.dev/api/v1
```

## Authentication

Requests authenticate with an API key in the `x-api-key` header:

```bash
curl https://prism.syntaxure.dev/api/v1/projects \
  -H "x-api-key: YOUR_API_KEY"
```

Create keys in the dashboard under **Settings** → **API Keys**, or with the CLI:

```bash
prism api-keys create
prism api-keys list
```

Keys are stored hashed (SHA-256) server-side. Each request records last-used time. Browser sessions (Supabase auth cookies) also work for the same routes.

## Endpoints

| Area | Path prefix | Notes |
|------|-------------|-------|
| Projects | `/api/v1/projects` | Create-time enforcement of the per-tier project cap |
| Rules | `/api/v1/rules` | List/create rules; sub-routes for `validate`, `creator`, `extract`, and a project's `pass` |
| Brands | `/api/v1/brands` | Brand profiles |
| Components | `/api/v1/components` | Saved components (tier-limited) |
| Skills | `/api/v1/skills` | Project skills |
| Analytics | `/api/v1/analytics` | Usage stats (tier-scoped) |
| API keys | `/api/v1/api-keys` | Key management (tier-limited count) |
| Marketplace | `/api/v1/marketplace` | Public rule sets |
| Sandbox | `/api/v1/sandbox` | Rules evaluation sandbox |

## Example: list rules

```bash
curl "https://prism.syntaxure.dev/api/v1/rules?limit=20" \
  -H "x-api-key: YOUR_API_KEY"
```

Responses use an envelope: `{ "data": ..., "meta": ... }`. Errors return `{ "error": "<message>" }` with an appropriate HTTP status.

## Rate limits and tiers

Routes apply per-tier rate limits and caps (for example project creation and AI generation counts) from the subscription tier attached to the key's owner. Free keys work; some AI-powered routes require a paid tier. See [Pricing](/pricing).
