# MCP Setup Troubleshooting

Fix MCP connection problems. The MCP server is started by the CLI (`npx @prism-engine/cli serve`); there is no separate `prism-mcp` binary and no `@prism/mcp-server` package.

## Checklist

- `@prism-engine/cli` is installed: `npx @prism-engine/cli --version`
- The IDE config file has a valid `prism` entry (see below)
- The config file is valid JSON
- The IDE was fully restarted after the config change
- The local cache is populated if you use offline mode (`prism sync`)

## IDE config files

`prism ide-setup` writes these for you:

| Editor | File |
|--------|------|
| Cursor | `~/.cursor/mcp.json` |
| Windsurf | `~/.windsurf/mcp.json` |
| Claude Desktop | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| VS Code | User `settings.json` (`prism.token`) |

The server block:

```json
{
  "mcpServers": {
    "prism": {
      "command": "npx",
      "args": ["@prism-engine/cli", "serve"],
      "env": { "PRISM_TOKEN": "<your token>" }
    }
  }
}
```

Validate JSON after any manual edit (`jq . ~/.cursor/mcp.json`).

## Test the server manually

```bash
# Offline (cache-only) mode
npx @prism-engine/cli serve --offline

# Send a test request in another terminal
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | npx @prism-engine/cli serve --offline
```

If the tools list returns, the server works and the problem is in the IDE config.

## Common issues

### Server not listed in the IDE

1. Config file in the wrong location (table above)
2. Invalid JSON in the config
3. IDE not fully restarted (quit and reopen, not just reload)

### `serve` falls back to lite mode

`prism serve` prints "Full MCP server unavailable, falling back to local cache" when the full `prism-mcp-server` cannot start. Lite mode serves rules from `~/.prism/rules/rules.json`. Run `prism sync` to populate the cache.

### No rules returned

1. No local cache — run `prism sync`
2. No cloud rules — create rules in the dashboard (project Rules tab) or run `prism init` locally
3. Not authenticated — `prism login` or set `PRISM_TOKEN`

### Token rejected

`prism login` stores the token in `~/.prism/token`. If it expired, log in again. `prism doctor` reports auth status.

### Network cannot reach the dashboard

The dashboard lives at `https://prism.syntaxure.dev`. Corporate proxies must allow that host for `pull`, `sync`, and authenticated `serve`. Offline mode (`--offline`) avoids the network entirely.

## Getting help

Open a GitHub issue with your OS, IDE, Node version, and the output of:

```bash
prism doctor --json
```
