# Common Issues

Real failure modes found in the CLI source, with fixes.

## Node version

The CLI requires Node.js 20 or newer (`engines: >=20`).

```bash
node --version
# need v20.x or higher
```

If you use nvm:

```bash
nvm install 20
nvm use 20
```

On Node 20, older CLI builds crashed on `import.meta.dirname`; this was fixed in CLI 1.1.2. If you see that error, update: `npm install -g @prism-engine/cli`.

## `command not found: prism`

The binary is `prism` (package `@prism-engine/cli`). Older docs called it `prism-mcp` — that binary does not exist.

```bash
npm install -g @prism-engine/cli
prism --version
```

If npm's global bin is not on your PATH, add it:

```bash
export PATH="$PATH:$(npm config get prefix)/bin"
```

## Hook silently skips checks

The hook fails open by design. If nothing enforces, check these in order:

1. **`PRISM_DISABLE=1`** — the kill switch. Unset it.
2. **No `.prism/rules.json`** — the hook prints `[prism] check skipped: no .prism/rules.json found` to stderr. Run `prism init`.
3. **Invalid rules file** — invalid JSON or a schema error (e.g. a bad category) makes the whole file fail validation; the hook logs the error to stderr and checks nothing. Validate by hand:

   ```bash
   prism check src/App.tsx
   ```

   The linter mode prints the parse error.

4. **File extension not covered** — a rule only applies to the extensions in its rule set. If no rule covers `.md`, `.md` files are skipped.
5. **Malformed event payload** — the hook never guesses. Unknown tool shapes exit 0.

Every run appends one line to `.prism/activity.log` (`CLEAN`, `BLOCKED <ruleId>`, or `SKIPPED <reason>`). That log tells you why a check did or did not fire.

## `prism pull` fails

`prism pull` fails safe — it keeps your existing `.prism/rules.json` and prints which problem it hit:

- **No API key** — set `PRISM_API_KEY` or add `"apiKey"` to `.prism/config.json`. Create keys in the dashboard under Settings.
- **Not logged in / expired token** — run `prism login`.
- **Network or server error** — the file is kept untouched; retry later.

## Hook fires twice in Cursor

Cursor can auto-map `.claude/settings.json` hooks while also having its own `.cursor/hooks.json` entry. Both running produces duplicate corrections. Remove one surface (see [Cursor](/integrations/cursor)).

## MCP server not starting

`prism serve` first tries to spawn the full `prism-mcp-server`; if it is unavailable, it falls back to a built-in lite server reading `~/.prism/rules/rules.json`.

- Lite mode means the full server could not start. Run `prism sync` to populate the cache.
- Test the server directly: `npx @prism-engine/cli serve --offline`.
- IDE not listing Prism: validate the MCP config JSON, then restart the IDE fully. `prism doctor` reports which IDEs are configured.

## Semantic layer never runs

The Gemini semantic layer is opt-in. All three are required:

```bash
export PRISM_GEMINI_CHECK=1
export GEMINI_API_KEY=your_key   # or GOOGLE_GEMINI_API_KEY
```

It also stays off when `PRISM_DISABLE=1`. Any failure (rate limit, timeout, bad response) fails open — the deterministic result stands and the activity log records the skip reason (`429-RATE-LIMIT`, `TIMEOUT`, ...). Set `PRISM_GEMINI_DEBUG=1` for stderr details.
