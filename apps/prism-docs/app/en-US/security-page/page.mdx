# Security and Privacy

How Prism handles your data, based on what the code actually does.

## Local-first enforcement

Rule checking runs on your machine:

- `prism init`, `prism check`, and the agent hooks read `.prism/rules.json` from your repo. No network calls.
- Your source code is not transmitted for rule checking. The check reads only the files you point it at.

## What leaves your machine (only if you opt in)

| Feature | What is sent |
|---------|--------------|
| `prism login` / `prism pull` / `prism sync` | Auth and API requests to the dashboard (`https://prism.syntaxure.dev`, overridable with `PRISM_API_URL`) |
| `prism rules/projects/brands/...` | Same dashboard API |
| Gemini semantic layer (opt-in) | The file being checked plus your rules text, sent to the Gemini API (`generativelanguage.googleapis.com`). Off unless you set `PRISM_GEMINI_CHECK=1` and provide a key. It has a 12-second hard cap and fails open |

## Dashboard architecture

- The dashboard apps are deployed on Vercel.
- The backend is Supabase (Postgres and Auth). Prism's tables live in the same Supabase project, accessed through a service-role client; each API route does its own user checks.
- The historical Azure Cosmos DB (MongoDB API) store was replaced by Supabase Postgres. See `docs/prism/PRISM_MIGRATION.md` in the repository.

## Secrets on your machine

| Path | Contents |
|------|----------|
| `~/.prism/token` | Dashboard auth token |
| `~/.prism/config.json` | API URL, last sync |
| `.prism/config.json` (project) | Optional API key for `prism pull` |

Treat these like any credential: do not commit them. The project `.prism/rules.json` file is safe to commit; the project `.prism/config.json` may contain a key — commit it only if it holds no secrets.
