# MCP Protocol

Understanding Model Context Protocol and how Prism uses it.


## What is MCP?

**MCP (Model Context Protocol)** is an open protocol that allows AI assistants to access external tools, data, and context. Think of it as a standardized "plugin system" for AI.

### Without MCP

```
┌──────────────┐     ┌──────────────┐
│  You (IDE)   │────▶│ AI Assistant │
│              │◀────│              │
└──────────────┘     └──────────────┘
        │
        │  "Use our design system"
        │  "Follow our patterns"
        │  "Here's 500 lines of context..."
        ▼
   😫 Manual prompt stuffing every time
```

### With MCP

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  You (IDE)   │────▶│ AI Assistant │────▶│  MCP Server  │
│              │◀────│              │◀────│  (Prism)     │
└──────────────┘     └──────────────┘     └──────────────┘
        │                                        │
        │  "Create a button"                     │
        │                                        │
        │                               Automatically fetches
        │                               your context rules
        ▼                                        ▼
   😎 AI already knows your patterns    📜 Fresh rules delivered
```

## How Prism Uses MCP

Prism's MCP server is started by the CLI (`prism serve`). It is configured per editor by `prism ide-setup`. It:

### 1. Runs Locally

```bash
npx @prism-engine/cli serve
```

The server runs on your machine over stdio. `prism serve` tries the full `prism-mcp-server` and falls back to a built-in lite server reading the local cache (`~/.prism/rules/rules.json`).

### 2. Fetches Your Rules

When your IDE's AI assistant starts, it queries the MCP server:

```
AI: "What tools/context do you have?"
MCP: "I have context rules for: styling, architecture, testing..."
```

### 3. Delivers Rules on Demand

When you ask the AI to generate code, it requests relevant rules:

```
AI: "I need styling rules for this button request"
MCP: "Here are the styling rules: [Ghost Glow pattern, color tokens, etc.]"
```

### 4. Serves Governance Tools

The server exposes tools for rule retrieval and validation (see the [MCP Server page](/api-reference/mcp-server) for the full list):

```
AI: "Validate this snippet against the rules"
MCP: *prism_check / validate_code_pattern returns findings*
```

## MCP Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                      YOUR MACHINE                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌──────────────┐     stdio      ┌──────────────┐          │
│  │   Your IDE   │◀─────────────▶│  MCP Server  │          │
│  │  (Cursor,    │                │  (prism-mcp) │          │
│  │   Windsurf)  │                └──────┬───────┘          │
│  └──────────────┘                       │                   │
│                                         │ HTTPS             │
│                                         │                   │
└─────────────────────────────────────────┼───────────────────┘
                                          │
                                          ▼
                               ┌──────────────────┐
                               │  Prism Cloud     │
                               │  (API + Rules)   │
                               └──────────────────┘
```

### Communication Flow

| Step | From | To | Protocol | Data |
|------|------|----|----------|------|
| 1 | IDE | MCP Server | stdio | Query for tools |
| 2 | MCP Server | Prism Cloud | HTTPS | Fetch rules |
| 3 | Prism Cloud | MCP Server | HTTPS | Rules JSON |
| 4 | MCP Server | IDE | stdio | Context for AI |

## MCP Tools Provided by Prism

The server registers 16 tools. The full list with descriptions is on the [MCP Server page](/api-reference/mcp-server). Examples:

### `get_architectural_rules`

Retrieve active architectural rules, optionally filtered.

### `validate_code_pattern`

Validate a code snippet against active rules.

### `prism_check`

Check files against rules.

## Debugging MCP

### Check MCP Status

Most IDEs show MCP server status in their UI. Look for:
- A plugin/extension icon
- "MCP" or "Tools" panel
- Server connection indicators

### Manual Testing

You can test the MCP server directly:

```bash
# Start in offline (cache) mode
npx @prism-engine/cli serve --offline

# In another terminal, send a test request
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | npx @prism-engine/cli serve --offline
```

### Common Issues

<Callout type="error">
  **"Tool not found"** — MCP server isn't running. Restart your IDE.
</Callout>

<Callout type="error">
  **"Authentication failed"** — API key is invalid or expired. Generate a new one.
</Callout>

<Callout type="error">
  **"No rules found"** — You haven't created any rules yet. Add rules in the dashboard.
</Callout>

## Security Considerations

### Token Storage

- The auth token lives in `~/.prism/token`; keep it out of version control
- `prism ide-setup` passes the token to IDE configs via the `PRISM_TOKEN` env var

### Data Flow

- The MCP server runs locally on your machine
- Rules come from your local `.prism/rules.json` and the local cache
- No code leaves your machine for rule serving

---

## MCP Protocol Specification

Prism follows the official MCP specification:

- **Transport**: stdio (standard input/output)
- **Protocol**: JSON-RPC 2.0
- **Server command**: `npx @prism-engine/cli serve`

For full protocol details, see [modelcontextprotocol.io](https://modelcontextprotocol.io).
