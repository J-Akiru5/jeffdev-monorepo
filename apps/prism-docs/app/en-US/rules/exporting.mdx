# Exporting Rules

How rules actually leave Prism today. Older docs described `prism rules export` subcommands and scheduled exports; those commands do not exist in the CLI and were removed from this page.

## 1. The rules file itself (local)

`.prism/rules.json` is plain JSON and version-controllable. Commit it and share it with your team through git — no export needed:

```bash
git add .prism/rules.json
git commit -m "Add project rules"
```

## 2. Dashboard export

On a project page in [prism.syntaxure.dev](https://prism.syntaxure.dev), the Rules tab has an **Export Rules** button. It downloads the project's rules for your editor.

## 3. Brand export (CLI)

Brand profiles export to editor and CSS formats:

```bash
prism brands export <slug> --format cursor    --output .cursorrules
prism brands export <slug> --format windsurf  --output .windsurfrules
prism brands export <slug> --format vscode    --output rules.md
prism brands export <slug> --format claude    --output claude-rules.md
prism brands export <slug> --format css       --output tokens.css
prism brands export <slug> --format tailwind  --output tailwind.config.js
```

Default format is `cursor`. Requires `prism login`.

## 4. REST API

Fetch cloud-side rules programmatically:

```bash
curl https://prism.syntaxure.dev/api/v1/rules \
  -H "x-api-key: YOUR_API_KEY" \
  -o rules.json
```

See the [API Reference](/advanced/api-reference).

## 5. Sync to a machine

```bash
export PRISM_API_KEY=your_key_here
prism pull --project my-slug
```

`prism pull` writes the team's rules into the local `.prism/rules.json` (same v1 schema `prism init` generates) and fails safe on any error.
